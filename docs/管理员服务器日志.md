# 管理员服务器日志

入口：管理后台 → 服务器日志，路由 `/admin/server-logs`。保留已有操作日志与访问统计页面。

## 功能与范围

- 后端运行日志：读取固定容器 `carbon-app` 的最近 stdout/stderr，包含时间戳与异常堆栈。
- Nginx 访问日志：读取 `/root/nginx/logs/access.log`。
- Nginx 错误日志：读取 `/root/nginx/logs/error.log`。
- 支持最近 100 / 200 / 500 / 1000 行、当前快照关键词筛选、手动刷新和每 10 秒自动刷新。
- 默认不轮询；页面隐藏时暂停，返回后重新读取。失败时停止自动刷新并支持重试。
- 只读，不支持命令执行、删除、下载全量文件或任意容器/路径。

这不是历史日志数据库或完整监控平台。原始日志仍由服务器现有 Docker/nginx 日志机制保存；页面按需读取，不复制到浏览器持久存储。日志轮转之前的文件、Java 文件 appender 日志不包含在当前入口中。

## 数据链路与权限

`ServerLogs.vue → logsApi → 主站 /api/admin/server-logs/tail → nginx → 内网 Python 读取器 → 本机 Carbon /getInfo → 固定日志源`。

接口：`GET /api/admin/server-logs/tail?source=carbon&lines=200`；`source` 仅接受 `carbon`、`nginx-access`、`nginx-error`，行数只接受上述四档。成功响应为 `{code:200,data:{source,lines,fetchedAt,truncated}}`。

使用项目统一 Axios 层添加 Bearer token；主站同源请求不使用 API 子域名。读取器每次向固定 `http://127.0.0.1:9090/getInfo` 校验身份，不解码未校验 JWT、不缓存权限、不存密码。只接受后端确认的管理员（userId=1、admin 角色或 `*:*:*` 权限），其他用户 403，登录失效 401，校验服务不可用 503，均不读取日志。

读取器仅监听 Docker 内网网关 `172.20.0.1:9126`，不绑定公网；nginx 只转发日志专用只读路径。内部 `/health` 不由 nginx 暴露。服务与 nginx 均返回 `Cache-Control: no-store, private`。

单次读取最多 512 KiB；Docker 命令固定、无 shell、4 秒超时；鉴权 3 秒超时，最多 8 个并发读取。Nginx 文件使用固定白名单、不跟随符号链接。输出对常见密码、token、API key、Cookie、Authorization、JWT 做尽力脱敏，但不能保证所有业务敏感字段均被识别。前端以文本插值呈现，不使用 `v-html`。

## 部署与维护

实现放在 `ops/server-logs/`，使用 Python 标准库，不添加第三方后端依赖、不改 Carbon 数据库、不重启 Java 服务。

主分支 push 继续触发现有 OSS + ECS workflow。新增步骤在修改 OSS **之前**执行测试、通过既有 SSH 密钥上传并幂等安装读取器；同样代码不重复重启服务。安装会验证 nginx 配置，仅新增日志专用 location，随后启动读取器并检查健康，最后热重载 nginx。

- 运行源码：`/usr/local/lib/blog-server-logs/agent.py`
- systemd 单元：`blog-server-log-agent.service`
- nginx 配置：`/root/nginx-full/nginx.conf`（带 BEGIN/END BLOG SERVER LOGS 标记）
- 部署暂存与备份：`/root/ops/server-logs/`；`backups/<UTC时间>/manifest.json` 记录原文件、权限与服务状态，失败时自动恢复。
- 诊断：`systemctl status blog-server-log-agent`、`journalctl -u blog-server-log-agent`、`docker exec nginx nginx -t`。
- 预检：`python3 /root/ops/server-logs/deploy.py --check`。

当前网关与路径来自实际 ECS 配置；若迁移服务器、修改 Docker 网络或容器名，须同步 agent、systemd 和 deploy.py，不能直接照搬地址。nginx 源文件路径与目录挂载对应，原路径不得改成单文件挂载后再使用原子替换。

本地：运行 Carbon（9090）与读取器（9126，默认监听 127.0.0.1），Vite 专用代理转发日志请求到 9126。无 Linux/Docker 日志源时可使用合成测试数据，勿为了测试取生产 token。

## 自检与偏差报告

- 架构：页面 → API → 类型；无新增 Store，无通用组件直接请求 API。
- 设计：复用管理布局、Element Plus 表单/卡片及语义主题 token；日志区域复用全局等宽字体。没有新颜色或 Primitive token。
- 部署偏差：后端目前无可用本地 Java 构建环境或自动发布链路，因此用独立只读读取器接入，不改现有 Java jar。此方案有独立 systemd 服务的维护成本，源码与自动部署同仓保存。
- 知识库：AGENTS.md 指定的四个 `.ai` 知识库文件不存在，未伪造已读取记录；依据项目指令、设计/产品/部署文档和真实源码实施。
- 安全：管理员权限由服务端验证；无任意路径、远程命令、生产凭据或日志正文进入 Git；认证失败不返回旧日志内容。
- 基础验证：Python 19 项单元/HTTP/回滚测试、`vue-tsc --noEmit` 与生产构建通过。现有大 bundle 警告未在本任务扩展处理。
- 浏览器验证：真实读取器 + 合成鉴权/日志验证页面加载、脱敏与 HTML 转义、关键词/无匹配、日志源/行数、10 秒轮询、失败暂停/重试、空日志/截断提示、移动端/深色主题、401 清除 token 与登录跳转；390px 视口无页面横向溢出。
- ECS 预检：源码语法和已有 nginx 配置通过，新增 location 定位唯一。发布状态以 GitHub Actions 为准；真实管理员生产会话需由账号持有人最终验收。
