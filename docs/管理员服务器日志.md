# 管理员服务器日志

入口：管理后台 → 日志管理（可展开/收起的父节点）。原有操作日志、服务器日志、访问日志放在子节点，新增 ECS 系统日志与 MySQL 备份/定时任务。桌面侧栏和移动抽屉使用同一层级。

## 功能与范围

- 后端运行日志：读取固定容器 `carbon-app` 的最近 stdout/stderr，包含时间戳与异常堆栈。
- Nginx 访问日志：读取 `/root/nginx/logs/access.log`。
- Nginx 错误日志：读取 `/root/nginx/logs/error.log`。
- MySQL 运行日志：固定容器 `main-mysql` 的 stdout/stderr。
- ECS 系统日志：`/admin/ecs-logs`，读取 `/var/log/syslog`、`/var/log/auth.log`、`/var/log/kern.log`；内核当前文件为空时读取固定上一轮 `/var/log/kern.log.1`。
- Docker 引擎与 cron 调度：筛选 syslog 最近 512 KiB 中的 dockerd/containerd、CRON/cron 行，页面明确标注范围，不冒充完整历史。
- 任务执行日志：固定 `/var/log/backup_mysql.log`、`/var/log/cleanup-docker-logs.log`、`/var/log/oss-cert-sync.log`。
- 支持最近 100 / 200 / 500 / 1000 行、当前快照关键词筛选、手动刷新和每 10 秒自动刷新。
- 默认不轮询；页面隐藏时暂停，返回后重新读取。失败时停止自动刷新并支持重试。
- 只读，不支持命令执行、删除、下载全量文件或任意容器/路径。

这不是历史日志数据库或完整监控平台。原始日志仍由现有 Docker/nginx/系统日志机制保存；页面按需读取，不复制到浏览器持久存储。除固定上一轮内核文件外，不搜索轮转历史、压缩文件或 Java 文件 appender 日志。

## MySQL 备份与 cron 的关联

页面 `/admin/maintenance`，只读接口 `GET /api/admin/server-logs/maintenance`，沿用同一管理员校验。每次读取实际 root crontab 和固定脚本元数据，不执行脚本、不读取数据库密码文件或 SQL 内容。

- 识别固定脚本直接执行、bash/sh/python3 调用；不把注释或 echo 脚本路径误认为任务。不返回其他 cron 命令或环境变量。
- 已接入数据库备份、Docker 日志清理、证书同步、ACME 续期四个现有脚本。
- 显示 cron 表达式、服务器时区、脚本是否可用、日志更新时间和查看执行日志链接。“已配置”不表示正在运行或执行成功。
- 本地目录固定 `/backup/mysql`，仅 `stat` 命名符合 `carbon_YYYYMMDD_HHMMSS.sql.gz[.partial]` 的普通文件，不跟随符号链接。最多扫描 1000 个目录项、展示扫描范围内最新 100 条，超限明确提示。
- 读取备份脚本明确声明的保留天数与 OSS bucket/prefix/storage class；不执行 shell 展开或输出整个脚本。
- 最近备份结果只依据日志中的时间戳和显式 OK/ERROR 终止标记；无证据显示未知，不根据文件 mtime 推断成功。
- 文件“已生成”不等于当前 OSS 归档对象已核验或一定可恢复。本次不重新调用 OSS、不下载数据库、不做恢复验证。
- 证书日志最近 20 行若存在 CdnServiceSuspended，显示固定诊断提示；不自动修改证书、CDN 或账号设置。
- 不含其他用户的 crontab 与 systemd timers，不提供手动备份、恢复、删除或计划编辑。用户尚未明确要求这些写操作。

## 数据链路与权限

`ServerLogs.vue → logsApi → 主站 /api/admin/server-logs/tail → nginx → 内网 Python 读取器 → 本机 Carbon /getInfo → 固定日志源`。

接口：`GET /api/admin/server-logs/tail?source=carbon&lines=200`；`source` 仅接受 `carbon`、`mysql`、`nginx-access`、`nginx-error`、`ecs-system`、`ecs-auth`、`ecs-kernel`、`ecs-docker`、`cron`、`mysql-backup`、`docker-cleanup`、`cert-sync`，行数只接受上述四档。成功响应为 `{code:200,data:{source,lines,fetchedAt,truncated}}`。概览接口不接受任何路径/命令参数，所有写请求仍被拒绝。

使用项目统一 Axios 层添加 Bearer token；主站同源请求不使用 API 子域名。读取器每次向固定 `http://127.0.0.1:9090/getInfo` 校验身份，不解码未校验 JWT、不缓存权限、不存密码。只接受后端确认的管理员（userId=1、admin 角色或 `*:*:*` 权限），其他用户 403，登录失效 401，校验服务不可用 503，均不读取日志。

读取器仅监听 Docker 内网网关 `172.20.0.1:9126`，不绑定公网；nginx 只转发日志专用只读路径。内部 `/health` 不由 nginx 暴露。服务与 nginx 均返回 `Cache-Control: no-store, private`。

单次读取最多 512 KiB；Docker 命令固定、无 shell、4 秒超时；鉴权 3 秒超时，最多 8 个并发读取。文件使用固定白名单、不跟随符号链接。元数据配置文件最大 32 KiB。新增系统日志读取组 `adm`，仍维持空 capability、只读文件系统、资源限制。输出对常见密码、token、API key、Cookie、Authorization、JWT 做尽力脱敏，但不能保证所有业务敏感字段均被识别。前端以文本插值呈现，不使用 `v-html`。

## 部署与维护

实现放在 `ops/server-logs/`，使用 Python 标准库，不添加第三方后端依赖、不改 Carbon 数据库、不重启 Java 服务。

主分支 push 继续触发现有 OSS + ECS workflow。新增步骤在修改 OSS **之前**执行测试、通过既有 SSH 密钥上传并幂等安装读取器；同样代码不重复重启服务。安装会验证 nginx 配置，仅新增日志专用 location，随后启动读取器并检查健康，最后热重载 nginx。

- 运行源码：`/usr/local/lib/blog-server-logs/agent.py`
- systemd 单元：`blog-server-log-agent.service`
- nginx 配置：`/root/nginx-full/nginx.conf`（带 BEGIN/END BLOG SERVER LOGS 标记）
- 部署暂存与备份：`/root/ops/server-logs/`；`backups/<UTC时间>/manifest.json` 记录原文件、权限与服务状态，失败时自动恢复。
- 诊断：`systemctl status blog-server-log-agent`、`journalctl -u blog-server-log-agent`、`docker exec nginx nginx -t`。
- 预检：`python3 /root/ops/server-logs/deploy.py --check`。

当前网关与路径来自实际 ECS 配置；若迁移服务器、修改 Docker 网络或容器名，须同步 agent、systemd 和 deploy.py，不能直接照搬地址。nginx 源文件路径与目录挂载对应，原路径不得改成单文件挂载后再使用原子替换。

本地：运行 Carbon（9090）与读取器（9126，默认监听 127.0.0.1），Vite 专用代理转发日志请求到 9126。无 Linux/Docker 日志源时可使用合成测试数据，勿为了测试取生产 token。

## 自检与偏差报告

- 架构：页面 → API → 类型；无新增 Store，无通用组件直接请求 API。
- 设计：复用管理布局、Element Plus 表单/卡片及语义主题 token；日志区域复用全局等宽字体。没有新颜色或 Primitive token。
- 部署偏差：后端目前无可用本地 Java 构建环境或自动发布链路，因此用独立只读读取器接入，不改现有 Java jar。此方案有独立 systemd 服务的维护成本，源码与自动部署同仓保存。
- 知识库：AGENTS.md 指定的四个 `.ai` 知识库文件不存在，未伪造已读取记录；依据项目指令、设计/产品/部署文档和真实源码实施。
- 安全：管理员权限由服务端验证；无任意路径、远程命令、生产凭据或日志正文进入 Git；认证失败不返回旧日志内容。
- 基础验证：Python 30 项单元/HTTP/回滚/元数据测试、`vue-tsc --noEmit` 与生产构建通过。现有大 bundle 警告未在本任务扩展处理。
- 浏览器验证：真实读取器 + 合成鉴权/日志验证页面加载、脱敏与 HTML 转义、关键词/无匹配、日志源/行数、10 秒轮询、失败暂停/重试、空日志/截断提示、移动端/深色主题、401 清除 token 与登录跳转；390px 视口无页面横向溢出。
- ECS 预检：源码语法和已有 nginx 配置通过，新增 location 定位唯一。发布状态以 GitHub Actions 为准；真实管理员生产会话需由账号持有人最终验收。

### ECS/备份扩展的验证报告与偏差

Story：管理员从日志树选择 ECS 或备份页面，经统一 API 和管理员校验，读取现有系统日志/cron/文件元数据，呈现只读结果并跳转执行日志。

| 边界 | 证据 |
|---|---|
| UI → 路由 | 浏览器确认父节点展开/收起、独立 ECS 页面，备份/MySQL/cron 按钮带正确 source 回跳 |
| 请求 → 接口 | 同源专用代理，真实读取器配合合成身份测试；401/拒绝命令参数/POST 拒绝有 HTTP 测试 |
| 接口 → 数据 | 正式同等资源/只读限制下，十二类源均成功读取；实际 root cron 四个任务、八个备份文件、最近 OK |
| 数据 → 响应 | 只返回脱敏日志与限定字段，未输出密码、原始 cron 环境变量或 SQL 内容；目录/配置缺失不报告成功 |
| 响应 → UI | 浏览器验证成功/失败/缺失/重试和旧数据清除；390px 视口无横向溢出、亮暗主题/移动抽屉/401 回跳通过；发布后由真实管理员验收会话 |

偏差：journal 查询在 CPUQuota=20%、4 秒限制下扫描历史过慢，因此改用固定文件及有界 syslog 筛选，而不是增加权限或放宽超时。内核显示当前或固定上一轮；Docker/cron 只显示最近系统日志片段，范围在界面明确标注。服务器已有备份和证书任务，本次不修改任何脚本/计划、不重复建任务。
