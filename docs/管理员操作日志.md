# 管理员操作日志

后台桌面侧栏和手机抽屉新增“操作日志”，地址 `/admin/operation-logs`。

复用现有后端 `GET /monitor/operlog/list`，通过主站 `/prod-api/monitor/operlog/list` 转发。请求显式使用同源 baseURL，沿用统一请求层的 Bearer token、401/403 和分页响应处理；开发环境新增 `/prod-api` 转发到本机 9090。权限由后端 `monitor:operlog:list` 校验，超级管理员沿用原权限规则。

支持操作模块、操作人、业务类型、执行结果、日期范围筛选，以及分页、刷新和详情。筛选在点击查询后应用；分页与刷新保持已应用条件。成功状态 0 正常传参；类型“其他”0 使用现有数组查询分支 `businessTypes[0]=0`，规避 mapper 把 0 视作空字符串的问题。日期参数沿用 `params[beginTime]` / `params[endTime]`，返回列表保持后端最新优先顺序。

已有文章、分类、标签和设置写接口通过 `@Log` 自动保存到 `sys_oper_log`，跨设备查询来自数据库。页面仅查看记录，无清空、删除或导出操作。详情展示模块、操作人、时间、IP、位置、请求路径、处理方法及错误信息，不展示可能包含文章全文或配置内容的原始请求/响应正文。

发布仍使用 `main` push 触发 OSS + ECS 流程；CDN 刷新名单包含新页面入口。

## 架构自检（deviation-report）

- 页面通过独立 API 模块调用统一 request；类型集中在 `src/types/logs.ts`。
- 复用 AdminLayout、Element Plus 和现有主题 adapter；样式使用现有 Semantic 与 Foundation token，亮暗主题不另设分支。
- 项目指令引用的 `.ai` 知识库不在本地，依据实际代码和设计文档实现；本地 memory 记录此缺失。
- 后端接口经生产转发验证，匿名访问返回业务 401；已登录真实数据验证需管理员会话。
